# Табылды

Платформа поиска и возврата потерянных вещей: Flutter-приложение на русском, кыргызском и английском, NestJS API и React-панель модерации. Пользовательские объявления не подменяются демонстрационными данными.

## Локальный запуск

Требуются Node.js 24+, npm и Flutter со встроенным Dart **3.13.2+**. Используйте версию Flutter, удовлетворяющую `mobile/pubspec.yaml`. В Windows запускайте `npm.cmd`, если PowerShell блокирует `npm.ps1`. Можно указать полный путь к Flutter через `FLUTTER_BIN`.

```powershell
npm.cmd run setup
npm.cmd run build
npm.cmd run dev
```

Откройте:

- приложение: http://localhost:8080;
- панель команды: http://localhost:5173;
- API и Swagger: http://localhost:3001/docs;
- состояние API: http://localhost:3001/v1/health.

`Ctrl+C` останавливает локальный запуск. Порт 3001 выбран, чтобы не мешать приложениям на 3000. При изменении порта укажите `PORT`, `PUBLIC_BASE_URL` и пересоберите Flutter с нужным `API_BASE_URL`. Запуск не устанавливает службы и не публикует приложение в интернете.

Сервер сам создаёт локальную PostgreSQL-совместимую БД PGlite, применяет миграции и заполняет категории и районы. Данные сохраняются в `backend/data`, фотографии — в `backend/storage`. Отдельная установка PostgreSQL для разработки не нужна. Не запускайте два сервера над одной папкой PGlite.

Настройки необязательны для разработки: скопируйте `backend/.env.example` в `backend/.env`, если нужно изменить параметры. `.env` читается сервером и служебными командами; переменные окружения имеют приоритет.

## AI

Работает сразу. Модель распознавания (MobileCLIP-S0, 45 МБ) скачивается сервером один раз при первом запуске в `backend/models` и проверяется по SHA-256; вручную — `npm run ai:model` в `backend`. Пока модели нет, определяется только цвет. Состояние: `/v1/health` → `aiRecognition: ready`.

С `ANTHROPIC_API_KEY` в `backend/.env` дополнительно работает Claude: читает модель на логотипе, пишет описание и проверяет фото на лица, номера и документы — тогда фото не требуют ручной проверки. Без ключа объявление с фото публикуется сразу, а модератор проверяет фото после публикации в «Обращениях» (локальная модель не умеет читать текст и находить лица, поэтому не объявляет фото безопасным). Чтобы скрывать такие объявления до одобрения, задайте `PHOTO_REVIEW=before`. В AI отправляется уменьшенная копия без EXIF/GPS.

Проверка на 25 реальных фото: категория верна в 23 из 23 оценённых, ~0,5 с на фото на CPU. Подписи категорий меняются в `backend/src/modules/ai/local/labels.ts`, после чего нужно пересобрать векторы (`scripts/build-ai-labels.ts`).

## Вход

В приложении выберите телефон или email. В локальном режиме код показывается в форме и журнале API. Это режим разработки; SMS/email при `OTP_DELIVERY=console` не отправляются.

Создайте администратора **до запуска API** или временно остановите его, если используется PGlite:

```powershell
cd backend
npm.cmd run admin:create -- admin@example.com "ЗаменитеНаСвойСильныйПароль!" SUPER_ADMIN
```

Пароль не предустановлен. Не используйте пример из инструкции в рабочей среде. Для production включена обязательная настройка MFA при первом входе.

## Что работает

- Гостевые каталоги, поиск, категории, район, цвет, сортировка, вознаграждение и загрузка следующих страниц.
- Публикация и редактирование, фото из камеры/галереи, черновик основных полей на устройстве, защита от повторного запроса.
- **AI-автозаполнение без ключей и без интернета.** После снимка сервер сам определяет категорию, цвет, узнаваемую марку (iPhone, Samsung, AirPods, Lenovo…) и пишет название на русском и кыргызском («Найден чёрный кошелёк» / «Кара капчык табылды»). В «Я потерял» категория, цвет и марка подбираются по набранному тексту. Всё можно поправить одним касанием; ручной выбор AI не перезаписывает. Фото паспорта или банковской карты распознаётся и не публикуется.
- Скрытые признаки, заявки на владение/сообщение о находке, запрос уточнений, решения и споры.
- Открытые комментарии под объявлениями («видел у остановки»): без телефонов и просьб о деньгах, автору приходит уведомление, автор удаляет комментарии под своим объявлением, на комментарий можно пожаловаться.
- «Связаться с нами» в профиле и в «Помощи»: идеи, проблемы и оценка приложения попадают в панель команды («Отзывы о платформе»).
- Переписка участников с историей и повтором отправки; мобильный клиент обновляет её через REST каждые 3 секунды. Сервер дополнительно поддерживает WebSocket.
- Передача вещи, одноразовый код, подтверждение сторонами, журнал возвратов через завершённые заявки.
- Жалобы, блокировки, уведомления внутри приложения, настройки языка/темы, отзыв сессий и обезличивание аккаунта.
- Админ-панель (на хостинге — по адресу `/admin`; первый администратор создаётся из `ADMIN_BOOTSTRAP_EMAIL`/`ADMIN_BOOTSTRAP_PASSWORD`, пока в базе нет ни одного): MFA, роли, модерация объявлений, обращения, заявки, участники, категории, feature flags, аудит и агрегированная статистика.

Фото документов, карт и ключей не публикуются. При отключённой AI-проверке фотографии стандартных категорий попадают на ручную проверку модератором (после публикации или до неё — `PHOTO_REVIEW`). Приватные превью используют ссылки на 5 минут; публичная выдача проверяет текущее состояние объявления.

## Граница готовности

Это рабочая локальная версия для пилотной проверки. Выпуск в магазины и публичное production-развёртывание требуют ваших доменов, SMS/email-сервиса, секретов, ключей подписи и Apple/Google-аккаунтов. Системные push-уведомления FCM/APNs, офлайн-очередь публикаций, QR-сканер и промышленный мониторинг пока не подключены. Полный список и обязательные проверки на устройствах находятся в [плане выпуска](docs/release.md).
