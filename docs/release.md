# Состояние выпуска · 10 ноября 2026

## Объём локальной версии

Восстановлены отсутствовавшие мобильные экраны и исходники админ-панели. Основные пользовательские процессы подключены к реальному API. Локальная БД пуста в части пользовательских объявлений; seed содержит только справочники.

Сборка для пилотной проверки не означает готовность публичного production или прохождение ревью магазинов.

## Автоматическая проверка

Результаты последнего завершённого прогона фиксируются в `verification.md`; воспроизводимая команда — `npm run check`. В CI отдельно выполняются backend format/lint/types/unit/e2e/build, сборка admin и Flutter analyze/test/web build.

API e2e использует настоящую NestJS-программу, in-memory PGlite, обработку изображений и WebSocket. Проверяет гостевой каталог, auth, фото с отключённым AI, запреты на приватный доступ, заявки, совпадения, чат, передачу, жалобы, роли, локализацию, аналитику, удаление аккаунта и отзыв сессий. Подписанные превью и блокировка публичного доступа до проверки/после удаления покрыты регрессией.

Flutter widget tests проверяют знакомство и сохранение выбора, кыргызский тёмный интерфейс на узком экране с увеличенным текстом, восстановление после ошибки ленты, обязательную авторизацию перед публикацией и сохранение кода передачи после обновления ответа сервера. Это не замена сквозного тестирования на телефоне.

## Известные ограничения

- Android SDK отсутствует в проверенной Windows-среде; APK/AAB и камера на физическом Android не проверены. iOS требует macOS/Xcode и не собирался.
- Визуальное ручное тестирование браузера не завершено: Computer Use не смог надёжно определить URL и остановил автоматизацию.
- FCM/APNs, фоновые системные push и регистрация мобильных push tokens не подключены. Уведомления внутри приложения работают.
- SMS/email требуют вашего HTTPS relay; тестируется адаптер с подменённым transport, реальная доставка не проверена.
- Локальное AI-распознавание (категория, цвет, марка, название RU/KY) работает без ключей; проверено на 25 фото и в веб-сборке (12.11.2026). Оно не читает текст и не находит лица, поэтому без `ANTHROPIC_API_KEY` фото с находкой уходит на модерацию. Работа Claude с реальным ключом не проверялась.
- Локальная модель скачивается с huggingface.co; если хост недоступен, укажите зеркало в `AI_LOCAL_MODEL_URL`. В Docker модели хранятся в томе `models`.
- Мобильный чат использует polling REST каждые 3 секунды; серверный WS протестирован отдельно. Нет mobile background sync.
- Черновик хранит основные поля. Нет долговечной очереди отправки, сохранения фото/скрытых признаков между перезапусками и автоматического повтора публикаций в фоне.
- В заявке доступны текст и фото из галереи; дополнительные уточнения на текущем экране добавляются текстом. Фото доказательств доступны участникам через короткую защищённую ссылку.
- Передача использует код и действия сторон. QR-генератор/сканер отсутствует.
- Поиск по фото/эмбеддингам, карта, организации, монетизация и расширенный trust scoring за пределами локального релиза.
- Админ-панель на русском; переводы пользовательского приложения требуют редакторской проверки носителями кыргызского, особенно защитных и юридических текстов.
- Текущие rate limits и scheduler рассчитаны на один API process. Redis/distributed queues не реализованы. Конкурентные записи и сбои между многошаговыми изменениями требуют транзакционного аудита перед масштабированием.
- Внешний security review, нагрузочные замеры, доступность 99,9%, store review, мониторинг, backup restore drill и юридическая проверка не выполнялись.

## Перед пилотом

1. Подключить staging, HTTPS, реальные OTP и тестовые аккаунты; проверить доставку и отзыв сессий.
2. Проверить на Android и iPhone гостевой просмотр → фото → модерация → заявка → чат → возврат двумя разными пользователями.
3. Повторить сценарии при отказе камеры, без интернета, после перезапуска, при просроченном коде и при блокировке участника.
4. Проверить тексты, контраст, screen reader и большие шрифты на обеих локалях.
5. Настроить подпись, правила обработки данных, поддержку, резервные копии и мониторинг. Провести восстановление и security review.
6. Ограничить пилот одной организацией/городом, назначить ответственного модератора и собирать обратную связь.
