# Данные, доступ и угрозы

## Матрица доступа

| Данные / действие | Гость | Автор объявления | Заявитель | Команда |
|---|---|---|---|---|
| Опубликованная карточка, примерный район | Да | Да | Да | По роли |
| Черновик / объявление на проверке | Нет | Да | Нет | SUPPORT/MODERATOR/SECURITY/SUPER |
| Скрытые признаки | Нет | Да | Нет | MODERATOR/SECURITY/SUPER |
| Заявка и evidence | Нет | Автор целевой вещи | Только своя | MODERATOR/SECURITY/SUPER |
| Чат | Нет | Если участник | Если участник | Через предусмотренные серверные операции |
| Контакты участника | Нет | Только свои маски | Только свои маски | SUPPORT/SECURITY/SUPER |
| Модерация объявлений/заявок | Нет | Только свои обычные действия | Нет | MODERATOR/SUPER |
| Ограничение учётной записи | Нет | Нет | Нет | MODERATOR/SECURITY/SUPER |
| Аудит и risk events | Нет | Нет | Нет | SECURITY/SUPER |
| Создание админов, feature flags | Нет | Нет | Нет | SUPER |

Сервер — источник прав; скрытие кнопок не является защитой. Access token проверяется вместе с существованием и состоянием device session. Выход, revoke-all и удаление аккаунта отзывают REST-доступ. WebSocket повторно проверяет сессию при входящих кадрах.

## Inventory

- Публичные: название, описание, тип, разрешённые фото, категория, примерный район, публичное имя и уровень доверия.
- Приватные: телефон/email и хеш назначения, скрытые признаки, evidence, переписка, защищённые оригиналы, device sessions, refresh hash, OTP HMAC.
- Административные: argon2-хеш пароля, MFA secret, административные JWT, аудит, риск-сигналы и решения.
- Аналитика: только разрешённые имена событий и безопасные свойства. Текст переписки, evidence, номера документов и точные координаты не отправляются в аналитику.

Секреты и рабочая БД не коммитятся. Приватность в хранилище и при резервном копировании зависит от настройки инфраструктуры; шифрование дисков/БД должно быть включено оператором. Административные TOTP secrets сейчас хранятся в БД, поэтому доступ к БД и резервным копиям особенно чувствителен.

## Угрозы и меры

| Угроза | Мера | Остаточная работа |
|---|---|---|
| Чужая приватная заявка | Object-level ACL; 404 вместо раскрытия существования | Внешний аудит |
| Подбор OTP | Срок, HMAC, счётчик попыток, rate limit | Проверка у реального relay |
| Отозванный JWT | Проверка device session в REST и WS | Политика для простаивающих WS соединений |
| Утечка фото до проверки | Подписанные preview URL, публичная выдача только активной опубликованной/возвращённой вещи | Проверка приватности S3 и CDN |
| Утечка по старому URL после удаления | Повторная проверка статуса и no-store | Уже скачанные копии удалить невозможно |
| Документы/карты/ключи | Категорийная политика запрещает публичное фото | Ручная проверка ошибочно выбранной категории |
| Ложное владение | Evidence, скрытые признаки, авторское решение, спор | Оператор не гарантирует юридическое право собственности |
| Мошенничество в чате | Предупреждения о деньгах/кодах/ссылках, жалобы и блокировки | Редакторская проверка защитных текстов носителями |
| Повтор операции | Idempotency-Key и clientMessageId | Конкурентные запросы/сбои посередине операции требуют отдельной нагрузки и транзакционного аудита |
| Захват админ-аккаунта | Argon2, краткий JWT, MFA и аудит | Внешний аудит хранения MFA и управления ключами |
| XSS | React escaping, отсутствие рендера пользовательского HTML | Production CSP и dependency monitoring |

Приватные preview/protected ссылки являются bearer-ссылками: любой получивший ссылку может открыть её до истечения 5 минут. Не размещайте их в публичных логах, аналитике или комментариях. Продакшен должен использовать HTTPS и приватные bucket'ы.

## Реакция на инцидент

1. Зафиксируйте время, request ID, симптомы и затронутые объекты; не копируйте OTP/evidence в общие чаты.
2. Ограничьте запись или доступ к скомпрометированному API, отзовите sessions и admin credentials, смените затронутые серверные секреты.
3. Сохраните защищённую копию журналов и БД для расследования. Проверьте audit и risk events.
4. Исправьте причину в staging, выполните регрессионные проверки и восстановление из согласованной копии при необходимости.
5. Согласуйте уведомления пострадавшим и необходимые юридические действия с ответственным специалистом.
6. Восстановите доступ после проверки; запишите причину, последствия и корректирующие меры.

Это инженерная модель угроз, не независимое заключение о безопасности и не юридическая политика конфиденциальности.
